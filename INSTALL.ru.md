# Установка Torgash

В этой папке — весь магазин: движок, модули, тема и PHP-библиотеки
(`vendor/`), так что Composer и Node на сервере не нужны.

## Что нужно серверу

- **PHP 8.5** с расширениями `pdo_pgsql mbstring intl gd fileinfo openssl curl
  zip bcmath dom xml iconv` (желательно `opcache sodium exif`, и `redis`, если
  потом будет Redis или Valkey), `proc_open()` не запрещён.
- **PostgreSQL 15 или новее** (Torgash делается и проверяется на 18).
- Веб-сервер, отдающий PHP в PHP-FPM: Caddy, nginx или Apache.
- **cron** и способ держать один процесс запущенным (systemd, supervisor).

Установщик проверяет всё это до того, как что-либо запишет:

    php artisan torgash:install --check --db-username=torgash --db-password=…

## Ubuntu 24.04 по шагам

Команды установки пакетов, файлов и пользователя базы — в `INSTALL.md`,
раздел «Ubuntu 24.04, step by step»: они одинаковые на любом языке.

### Установка

**В браузере**: направьте домен на папку, откройте его — мастер `/install`
сделает всё то же, что команда. Сначала он спросит код из файла
`storage/app/install-key` (кто может прочитать файлы сервера, тот и
владелец) и ставит по шагу на запрос, так что ограничение хостинга по
времени установку не оборвёт.

**Из консоли**:

```bash
cd /var/www/torgash
sudo -u www-data php artisan torgash:install \
  --url=https://shop.example.com --name="Мой магазин" --locale=ru --currency=UAH --country=UA \
  --db-username=torgash --db-password='…' --db-database=torgash \
  --modules=store --owner=you@example.com
```

Чего нет в флагах — спросит. `--modules`: `minimal`, `store` (по умолчанию)
или `all`, либо id модулей через запятую. `--country` добавляет к набору
службы доставки и платёжные шлюзы этой страны; модули других стран лежат в
папке неустановленными — их можно поставить или удалить потом. Без `--owner-password` пароль
придумывается и показывается один раз.

Если что-то упало — исправьте и запустите ту же команду ещё раз: установщик
продолжит с того места. Поверх законченной установки он не запустится.

**Локаль базы важна.** Установщик создаёт базу с ICU-локалью `und` и перед
завершением проверяет русский поиск. Если создаёте сами — так: под локалью
`C` PostgreSQL не считает кириллицу буквами, и поиск работает наполовину без
единой ошибки:

```sql
CREATE DATABASE torgash TEMPLATE template0 ENCODING 'UTF8'
  LOCALE_PROVIDER icu ICU_LOCALE 'und' LC_COLLATE 'C.UTF-8' LC_CTYPE 'C.UTF-8';
```

`LC_COLLATE`/`LC_CTYPE` — имена локалей самой системы (их список: `locale -a`):
на Linux `C.UTF-8` или `en_US.UTF-8`. Только не просто `C`.

### Веб-сервер, фоновая работа

Пример Caddyfile, строка cron и служба systemd для очереди — в `INSTALL.md`.
Не давайте веб-серверу подменять страницы ошибок PHP (никакого
`handle_response` на 5xx): магазин рисует свои, а закрытая витрина отвечает
503 намеренно.

Без отдельного воркера очереди планировщик сам запускает короткий каждую
минуту, так что на хостинге без постоянных процессов хватит одной строки
cron. Если воркер работает службой systemd, напишите в `.env`
`QUEUE_WORKER=external`.

**PHP внутри FrankenPHP** (или любой сервер, где `php` — обёртка): задайте
переменную окружения `PHP_BINARY=/usr/local/bin/php` (путь к настоящему PHP
для командной строки) для строки cron и всех служб. По ней планировщик
запускает свои задачи, по ней же работают обновления и их откат.

## Потом

- **Обновления** — Админка → Система → Обновления: подписанный пакет,
  сначала резервная копия, при сбое откат сам.
- **Почта, оплата, доставка** — в админке.
- **Резервные копии** — Админка → Система → Резервные копии; восстановление
  только из консоли, `php artisan torgash:backup-restore`.
- Забыт пароль владельца: `php artisan torgash:admin you@example.com`.
