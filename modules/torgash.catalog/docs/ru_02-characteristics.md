# Характеристики

Характеристики товара хранятся в двух местах. На странице товара они выглядят
одинаково, но это не две копии одной таблицы, и делают они разное.

## Характеристики магазина

Каталог → Характеристики. У каждой есть название, код и обычно список
значений («Цвет»: чёрный, белый, синий). В товаре это карточка
**«Общие характеристики»** на вкладке «Характеристики».

С ними магазин **работает**:

- панель фильтров и страницы фильтров;
- вариации — товары одной группы различаются по ним;
- бренд и страница бренда;
- метки, которые печатают `[feature:КОД]`;
- краткое описание, собранное из характеристик.

Где характеристика показывается, задаётся в ней самой, в «Где
показывается»: панель фильтров, характеристики на странице товара, короткий
список под кнопкой покупки. Даже если снять все три галочки, она продолжает
работать в адресах, страницах фильтров и вариациях.

## Индивидуальные строки товара

Карточка **«Индивидуальные характеристики»** на той же вкладке. Это слова
для страницы одного товара: «Гарантия: 2 года», «Комплект: кабель, чехол».
Они печатаются под характеристиками магазина, находятся поиском и видны в
сравнении в разделе «Прочее». **По ним ничего не фильтруется**, вариаций они
не образуют, метки и краткое описание их не видят.

Несколько мест читают оба хранилища, но сначала — характеристики магазина:
`{feature:…}` в шаблонах и текстах, условия доставки и настройка веса. Они
ищут характеристику магазина с таким кодом (или названием) и только если её
нет, берут индивидуальную строку с точно таким же названием.

Фид (строки `<param>` для Яндекс Маркета, `item.params` в шаблоне экспорта)
выводит сначала характеристики магазина, потом индивидуальные строки.
Индивидуальная строка с тем же названием, что у характеристики, значение
которой у товара уже есть, в фид не попадает: две строки с одним названием
маркетплейс считает ошибкой.

## Какая из них главная

Если факт нужен не только странице — по нему фильтруют, по нему различаются
товары, его показывает метка, — он должен быть среди **характеристик
магазина**. Индивидуальная строка с тем же названием — только слова на
странице.

Если поменять цвет в индивидуальных строках, изменится только текст на
странице: фильтр по-прежнему найдёт товар под старым цветом, потому что
фильтр читает характеристику магазина.

## Когда страница показывает одно и то же дважды

Если у товара есть значение характеристики магазина, которая показывается в
характеристиках, **и** индивидуальная строка с тем же названием, страница
печатает обе:

    Оперативная память    16 ГБ
    Оперативная память    16 ГБ DDR4, два слота

Форма товара предупреждает об этом над индивидуальными строками, а Безопасность →
Инварианты показывает все такие товары («Ни одна страница товара не печатает
характеристику дважды»). Сами данные никто не трогает — выхода два, и оба
правильные:

- **Своя строка — просто подробная формулировка.** Фильтру нужно «16 ГБ»,
  странице — подробности. Откройте характеристику и снимите в «Где
  показывается» галочку «Характеристики»: фильтровать она продолжит, а
  страница напечатает только вашу строку.
- **Своя строка — остаток.** Удалите её: значение уже в характеристике
  магазина.

## Импорт, 1С и API

Каждый источник пишет в одно место, никогда в оба:

| Источник | Куда попадает |
|---|---|
| Колонка с названием характеристики («Цвет») | в характеристику магазина |
| «Цвет: S[Чёрный]; Память: S[128 ГБ]» | в характеристики магазина (недостающие создаются) |
| Бренд, «VAR Feature 2 [Цвет]» | в характеристики магазина |
| JSON-список разделов и строк в колонке «Характеристики» | в индивидуальные строки товара, как написано |
| 1С (CommerceML) | в связанные характеристики магазина |

Строка JSON с названием характеристики магазина остаётся индивидуальной
строкой: импорт не угадывает и никогда не придумывает значения фильтров из
свободного текста. Если нужно, чтобы по ней фильтровали, вынесите её в
отдельную колонку.

API показывает оба места: `characteristics` (характеристики магазина, с
кодами) и `features` (индивидуальные строки товара).
