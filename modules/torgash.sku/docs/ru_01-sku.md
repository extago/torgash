# Шаблоны артикулов

Артикул товара по шаблону — текст как есть, а в фигурных скобках то, что
меняется от товара к товару:

| В скобках | Что даёт |
|---|---|
| `{n}`, `{n:6}` | сквозной номер (дополненный нулями до 6 цифр) |
| `{id}` | номер самого товара |
| `{category}`, `{category:3}` | адрес категории заглавными (первые 3 символа) |
| `{brand}`, `{brand:3}` | код бренда |
| `{year}`, `{yy}` | текущий год |
| `{rand:4}` | случайные буквы и цифры (без O/0 и I/1 — их путают) |
| `{digits:4}` | случайные цифры |
| `{ean13}` | целый EAN-13 с контрольной цифрой, начинается с 2 |

`SKU-{n:6}` даёт `SKU-000001`, `{category:3}-{yy}-{n:4}` — `SMA-26-0001`.
Подстановка, которой нечего сказать (у товара нет бренда), ничего не печатает,
а оставшийся двойной дефис убирается.

## Когда срабатывает

Каталог → Шаблоны артикулов, «Присваивать новому товару артикул по шаблону»:

- **Когда артикул не указан** — безопасный выбор. Оставьте поле пустым в
  карточке товара (или в импорте) — его заполнит шаблон; артикул, введённый
  вручную или пришедший из 1С, сохраняется.
- **Всегда** — даже поверх введённого вручную. Для магазина, у которого
  артикулы только свои.
- **Никогда** — шаблон работает только при перенумерации (ниже).

Без этого модуля товар, созданный с пустым артикулом, получает `P-<номер>`.

## Шаблон для категории

У категории может быть свой шаблон, его берут и подкатегории; категория без
шаблона берёт шаблон родителя, а если его нет — общий. Товар в нескольких
категориях берёт самую вложенную.

Категории привязываются к товару после его создания, поэтому артикул сначала
делается по шаблону, который действует в этот момент, а после сохранения
карточки — заново по шаблону категории. Импорт оставляет общий шаблон —
перенумеруйте категорию после него.

## Сквозные номера

У каждого шаблона своя последовательность: две категории с одинаковым
шаблоном делят её, поэтому два товара не получат один артикул. Два товара,
созданные в одну и ту же секунду, никогда не вытянут один номер.

## EAN-13

`{ean13}` делает правильный EAN-13, начинающийся с 2, — диапазон, который
GS1 оставляет для собственных товаров магазина: для его сканера и этикеток.
Маркетплейсу нужен номер участника GS1 — его выдаёт GS1, а не шаблон.

## Перенумерация уже существующих товаров

Идёт в фоне (Система → Фоновые задачи) и сохраняет каждый товар через каталог, поэтому
в аудите остаётся каждый старый артикул:

- **Только товары, которым никто не задал артикул (P-…)** — наводит порядок
  после товаров, созданных с пустым артикулом до включения модуля;
- **Все товары** — включая введённые вручную, счётчик продолжается с того
  места, где он сейчас. Артикул, который хочет шаблон, может ещё принадлежать
  товару, до которого очередь не дошла; он пропускается, поэтому в нумерации
  бывают дыры;
- **Очистить все артикулы и пронумеровать все товары заново с 1** — весь
  магазин: счётчики сбрасываются, а все старые артикулы сначала
  откладываются, поэтому товары получают 1, 2, 3… в порядке добавления, без
  пропусков. Если задачу остановить, старые артикулы возвращаются; товар,
  оставшийся с временным артикулом `~~…`, экран посчитает — запустите
  снова, чтобы закончить.

Импорт, 1С или маркетплейс, которые знают старые артикулы, больше не найдут
по ним товары — поэтому экран сначала переспрашивает.

## Артикулы и 1С

В режиме «Всегда — даже поверх введённого» товар, созданный обменом, сразу
получает артикул по шаблону. При СЛЕДУЮЩЕМ обмене 1С присылает свой артикул
снова и записывает его обратно — если в настройках CommerceML в «Заполнять
только при первом импорте» не отмечен «Артикул». Отметьте его, когда
артикулы магазина свои: 1С всё равно узнаёт свои товары по идентификатору,
а не по артикулу.

Первые два можно ограничить категорией вместе со всеми вложенными.
