# Лендинги товаров

Лендинг — часть страницы товара из HTML и CSS со своими картинками: промо,
«почему мы», дизайнерская страница для целой линейки. Пишется один раз и
показывается на всех товарах, к которым подходит.

## Где стоит

- **Над описанием** и **под описанием** — вокруг собственного текста товара,
  в его разделе «Описание».
- **Вместо описания** — на странице лендинг, а не текст. Само описание
  остаётся у товара: им по-прежнему пользуются фиды, экспорт, `.md`-страница
  и meta description. У товара без своего текста, но с лендингом «вместо»
  раздел «Описание» всё равно есть.
- **Отдельная вкладка** — раздел со своим названием, среди остальных по
  порядку (описание — 10, характеристики — 20). Потом его можно
  переименовать или передвинуть, как любой раздел.

Лендинги в одном месте идут по порядку, меньшее — первым.

**Сворачивать, как описание** (кроме вкладки): длинный лендинг показывает
первый экран, затухание и кнопку **Читать полностью** — на высоте, заданной
для описания (Настройки → Каталог; 0 там — ничего не сворачивается).
Развёрнутый лендинг оставляет читателя на месте, свёрнутый обратно —
возвращает к своему началу. По умолчанию выключено.

## Для каких товаров

- **Товары, выбранные вручную**, его видят.
- **Условия** — те же правила показа, что у блоков и баннеров: категория (с
  подкатегориями), метка, наличие, «описания нет», витрина, язык, группа
  покупателя, город посетителя, даты, дни недели, часы.
- Если нет ни того, ни другого — его видят **все товары**.
- **Исключённый** товар не видит никогда, что бы ни говорили условия —
  «все ноутбуки, кроме этого».

Сверху действуют «Показывать с / до» и переключатель. В карточке товара
вкладка «Лендинги» показывает, какие лендинги у него есть и почему, и
позволяет ответить за этот товар отдельно: как в лендинге, показывать
здесь, никогда здесь.

## Текст на каждом языке

HTML пишется на каждом языке, как любой текст в админке (выбор языка
наверху). Язык без своего текста показывает базовый. CSS — один на все языки.

## Свой CSS

Лендинг стоит в собственном shadow root: стили магазина внутрь не попадают
(дизайнерский `.hero` или `.card` — не классы daisyUI), а его стили не
вытекают наружу. Шрифт и цвет текста страницы наследуются. В CSS `:host`
(или `:scope`) — это сам лендинг. `@font-face` работает; `@import`
отбрасывается — приносите шрифты файлами.

## Файлы

Картинки (WebP, PNG, JPEG, GIF, AVIF), шрифты и видео загружаются в форме
лендинга, а в HTML и CSS называются `assets/имя.webp`. Каждый файл
проверяется по содержимому, а не только по имени. SVG не принимается: с
адреса магазина он может выполнить скрипт.

## Данные товара внутри

Подстановки вставляют данные товара: `{product_name}`, `{price}`,
`{old_price}`, `{product_sku}`, `{brand}`, `{feature:код}` и всё остальное
из списка подстановок. Тогда один лендинг на категорию говорит о каждом
товаре своё.

## Без скриптов

HTML очищается при выводе, как всё, что пишут сотрудники: без `<script>`,
`onclick` и форм. Анимации — на CSS. Виджет, которому нужен JavaScript,
подключается через «Код и скрипты» со своими правилами показа.

## ZIP

Папка дизайнера в ZIP — `index.html`, `style.css`, `assets/…`, можно внутри
одной папки; `index.ru.html` и подобные — для других языков. «Новый из ZIP»
в списке создаёт лендинг (выключенный, пока вы его не посмотрите); «Заменить
из ZIP» в лендинге заменяет HTML, CSS и файлы, а «где» и «для кого»
сохраняет. Целый HTML-документ обрезается до содержимого `<body>`, его
`<style>` переезжают в CSS, `<script>`, `<link>`, `<meta>`, `<title>`
отбрасываются, и экран сообщает, что именно. «Скачать ZIP» отдаёт то же
самое обратно.

## Посмотреть до включения

«Посмотреть» в форме открывает товар с лендингом в сохранённом виде, даже
если он выключен, — только для сотрудников, которым можно править лендинги.
