# Сопоставление пунктов

Новая Почта адресует отделения по `Ref` пункта (UUID), никогда по имени.
Поэтому, прежде чем модуль сможет предложить перевозчика для города, город надо
связать с пунктом Новой Почты. Родные модули перевозчика решают это, *продавая*
предсопоставленный пакет данных; этот модуль вычисляет соответствие по API.

## Как находится соответствие

`Сопоставить с реестром` идёт по цепочке, останавливаясь на первом однозначном
шаге:

1. **имя + область + район**
2. **имя + область** — только когда остаётся ровно один кандидат
3. **почтовый индекс** — индекс пункта перевозчика попадает в диапазон
   `postal_from..postal_to` места, и такой кандидат один
4. **координаты** — ближайший кандидат, но только если он ближе 30 км *и*
   вдвое ближе следующего
5. **имя уникально по стране + координаты сходятся** — для Киева, Севастополя
   и подобных, где стороны называют область по-разному

Всё, что осталось неоднозначным, отдаётся человеку. Повторный прогон заменяет
все автоматические привязки; привязку, сделанную вручную (`manual`), не трогает
никогда.

## Список несопоставленных

На экране данных перечислены места без соответствия. Для каждого пикер ищет по
справочнику перевозчика и показывает для каждого кандидата расстояние и попадает
ли его индекс в диапазон — так восемь одинаковых «Іванівок» перестают быть
подбрасыванием монеты. **Это** — привязать, **Отвязать** — отменить.

## Почему часть пунктов не сопоставится никогда

На живых украинских данных примерно 2 800 мест не имеют пары у Новой Почты
вовсе: Крым и Севастополь (у перевозчика там ноль строк), значительная часть
Донецкой и Луганской областей и сёла, которые перевозчик просто не обслуживает.
Такие места не предлагают Новую Почту — ровно как и родной модуль перевозчика.
