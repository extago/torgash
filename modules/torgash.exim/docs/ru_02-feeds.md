# Файлы и фиды

Профиль экспорта — это один файл: какие данные, какие колонки, какой формат.
Его можно скачать из админки или дать его адрес тому, кто забирает файл:
CRM, оптовику, маркетплейсу.

Обмен данных → Профили экспорта.

## Фид для Яндекс Маркета

Создайте профиль для товаров в формате XML, «Строится из» — **своего
шаблона**, и в списке **«Начать с готового шаблона»** выберите
«Yandex Market (YML)». Условия доставки в нём — пример, поменяйте на свои.

Характеристики попадают в строки `<param>`: сначала характеристики магазина,
потом индивидуальные строки товара (карточка **«Индивидуальные
характеристики»**). Индивидуальная строка с тем же названием, что у
характеристики, значение которой у товара уже есть, не выводится: две строки
с одним названием маркетплейс считает ошибкой.

Чтобы отправлять только характеристики магазина, поставьте строку внутрь
`{{^own}}`:

```
{{#item.params}}{{^own}}<param name="{{ name }}">{{ value }}</param>{{/own}}{{/item.params}}
```

## Какие товары попадают

Карточка **«Какие товары»** в профиле товаров. Пустое поле берёт всё; вместе
поля сужают выборку, товар должен пройти все.

- **Статусы** — по умолчанию только включённые, то есть то, что показывает
  каталог; отметьте скрытые или выключенные, чтобы взять и их.
- **Наличие** — статусы наличия магазина (в наличии, под заказ, нет в наличии, свои): статус товара — один из отмеченных.
- **Цена от / до** в валюте магазина, **остаток от / до** и три
  переключателя: только то, что можно заказать сейчас (статус наличия
  позволяет и, если он считает остаток, остаток есть), только с описанием (на
  любом языке), только с фото (своим или по адресу, пока магазин разрешает
  картинки по адресу).
- **В категориях / не в категориях** — списки с галочками и поиском по
  названию, каждый с подкатегориями или без. Ничего не отмечено в первом — все
  категории.
- **С меткой** — хотя бы одна из отмеченных.
- **Характеристики** — сколько угодно условий по характеристикам магазина:
  *равно*, *не равно*, *одно из* (через запятую), *ни одно из*, *содержит*,
  *не содержит*, *больше*, *не менее*, *меньше*, *не более*, *пусто*,
  *заполнено*. Значение сравнивается как текст на каждом языке без учёта
  регистра; числовые сравнения берут число в начале значения, так что
  «128 ГБ» — это 128. *Не равно*, *ни одно из*, *не содержит* и *пусто*
  пропускают и товар, у которого такой характеристики нет вовсе. При двух и
  более условиях вы выбираете, должен ли товар пройти все или любое.
- **Взять ещё эти артикулы** — товары по артикулу: либо *в дополнение* к
  категориям и характеристикам выше (по умолчанию), либо *только те из них,
  что проходят* условия выше. **Никогда не брать эти артикулы** сильнее всего.
- **Стоп-слова** — товар, у которого любое из слов встречается в отмеченном
  поле (название, краткое описание, описание, SEO-заголовок и описание) на
  любом языке, не попадает: `восстановленный`, `витринный образец`.

Карточка показывает, сколько товаров подходит сейчас; число считается при
открытии формы, то есть по последнему сохранению.

## Как файл остаётся свежим

Два способа в карточке **«Обновление файла»**: любой из них, оба или ни
одного.

**По расписанию.** Выберите из списка или впишите выражение cron сами — пять
полей: минута, час, день месяца, месяц, день недели:

| Выражение | Когда |
|---|---|
| `0 3 * * *` | каждый день в 03:00 |
| `*/30 * * * *` | каждые 30 минут |
| `0 9-21 * * 1-5` | каждый час с 9:00 до 21:00, с понедельника по пятницу |
| `0 6,18 * * *` | в 06:00 и в 18:00 |

Под полем сразу видны три ближайшие сборки.

**Когда меняются его данные.** Раз в пять минут магазин смотрит, изменилось
ли с последней сборки то, что читает экспорт: товары, категории,
характеристики, цены, фото, остатки. Ничего не изменилось — файл не
собирается. Изменилось — собирается заново, но не чаще выбранного интервала:
пятьдесят правок за час дают две сборки, а не пятьдесят. Просмотр страницы
товара изменением не считается.

Расписание стоит оставить и вместе с этим: некоторые изменения не оставляют
следа в данных — например, акция, которая начинается в полночь.

**Ни того ни другого** — адрес собирает свежий файл при каждом запросе.

## Адрес фида

Если включено расписание или сборка по изменениям, адрес сразу отдаёт
последний собранный файл, как часто его ни запрашивай. Файлы собираются в
фоне: в «Система → Фоновые задачи» видна каждая сборка и её причина, а в
профиле — когда файл собран, сколько в нём строк, размер и сколько заняла
сборка. Хранится только последний файл.

Всё это работает, только если сервер каждую минуту запускает планировщик
магазина — команда показана в профиле.
