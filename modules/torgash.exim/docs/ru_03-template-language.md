# Язык шаблонов

Профиль экспорта, который строится из **своего шаблона**, пишет файл вокруг
данных магазина: фид маркетплейса (Яндекс Маркет, Авито, Google), XML для
CRM, прайс любой формы. Шаблон — это текст с тэгами. Язык — подмножество
Liquid, на котором владельцы магазинов Shopify пишут свои темы, так что фид,
написанный для Shopify, здесь читается так же.

Ничто в шаблоне не выполняется как код. Тэг может вывести значение,
проверить его, пройти по списку, запомнить результат под именем и пропустить
через фильтры движка. Он не может обратиться к магазину, прочитать файл или
дотянуться до чего-то, кроме переданных ему данных. Шаблон, который делает
слишком много работы на одной строке, останавливается, и ему об этом
говорится — с номером строки.

## Значения

```
{{ item.sku }}
{{ item.name.ru }}
{{ item.price | price }}
{{ shop.name }}
```

Внутри блока строк товар — это `item`: колонка — `item.<ключ>`, текст на
одном языке — `item.<ключ>.<язык>`, цена типа цен — `item.price_type.<КОД>`,
характеристика — `item.feature.<код>`. Товарный фид даёт ещё `item.id`,
`item.url`, `item.available`, `item.category_id`, `item.price`,
`item.old_price`, `item.brand`, `item.pictures` (список адресов) и
`item.params` (список характеристик с полями `name`, `value`, `code`,
`own`). Колонка, названная в шаблоне, читается, даже если в профиле она не
отмечена.

Вне строк: `profile.name`, `profile.generated_at`; для товаров `shop.name`,
`shop.url`, `shop.company`, `shop.currency`, `shop.currencies` (`id`,
`rate`), `shop.categories` (`id`, `parent_id`, `name`).

Элемент списка по номеру: `item.pictures.0`, по значению:
`item.name[shop.locale]`. Имени, которого нет, — просто пусто.

Каждое значение экранируется под формат файла, так что кавычка в названии
товара не сломает XML или JSON. `| raw` выводит как есть, `| cdata`
оборачивает в `<![CDATA[ … ]]>`; в простом текстовом файле ничего не
экранируется, пока не попросите `| escape`.

## Фильтры

Фильтр меняет значение перед выводом; несколько идут подряд, слева направо.
Аргумент пишется после двоеточия, несколько — через запятую. Аргументом
может быть и значение: `| default: shop.name`.

```
{{ item.description | strip_tags | squish | truncate: 3000 | cdata }}
{{ item.name | remove: item.brand | trim }}
{{ item.weight_g | divide: 1000 }}
```

| Фильтр | Что делает |
|---|---|
| `price` | цена за единицу числом: 7199000 → 71990 |
| `money` | копейки как сумма: 1250 → 12.50 |
| `divide: N`, `multiply: N`, `plus: N`, `minus: N`, `modulo: N` | арифметика (также `divided_by`, `times`) |
| `round: N`, `ceil`, `floor`, `abs`, `at_least: N`, `at_most: N` | округление и границы |
| `number: N` | ровно N знаков после запятой |
| `strip_tags` (`strip_html`), `squish`, `strip_newlines` | без HTML, пробелы в один, без переносов |
| `truncate: N`, `truncatewords: N` | не длиннее N символов / слов |
| `lower` (`downcase`), `upper` (`upcase`), `capitalize` | регистр |
| `trim` (`strip`), `lstrip`, `rstrip` | пробелы по краям |
| `replace: "a", "b"`, `replace_first: "a", "b"`, `remove: "a"` | замена текста (регистр важен) |
| `append: "текст"`, `prepend: "текст"` | текст после / перед |
| `slice: от, длина` | кусок текста (0 — первый символ; -3 — последние три) |
| `split: ","` | текст, разрезанный в список |
| `join: ", "`, `first`, `last`, `size`, `reverse`, `sort`, `sort: "поле"`, `uniq`, `compact` | списки |
| `map: "поле"`, `where: "поле", "значение"` | одно поле каждой записи; только подходящие записи |
| `default: "текст"` | этот текст, если значение пустое |
| `date: "d.m.Y"` | дата в таком виде (буквы PHP) |
| `url_encode` | безопасно внутри веб-адреса |
| `cdata`, `raw`, `escape` | как выводится значение |

Арифметика передаёт дальше число, так что `| divide: 1000 | plus: 1`
прибавляет к 0.171, а не к «0.171». Число печатается с не более чем
четырьмя знаками; `number: N` — ровно N.

## Условия

```
{% if item.old_price > item.price %}
<oldprice>{{ item.old_price | price }}</oldprice>
{% endif %}

{% if item.feature.condition contains "как новый" %}
<Condition>Как новый</Condition>
{% elsif item.feature.condition contains "б/у" %}
<Condition>Б/у</Condition>
{% else %}
<Condition>Новое</Condition>
{% endif %}

{% unless item.available %}<Stock>0</Stock>{% endunless %}
```

Условие — это выражение: `==` (или `=`), `!=`, `<`, `>`, `<=`, `>=`,
`contains` (текст содержит слова, список содержит значение — регистр не
важен), `and`, `or`, `not`, скобки, `+ - * /`, `&` для склейки текста и
функции ниже. Два числа сравниваются как числа, всё остальное — как текст
без учёта регистра. Ничто, false, 0, пустой текст и пустой список считаются
ложью.

Функции: `if(проверка, тогда, иначе)`, `empty(x)`, `default(x, другое)`,
`contains(текст, часть)`, `starts_with`, `ends_with`, `len(x)`, `lower`,
`upper`, `capitalize`, `trim`, `left(текст, n)`, `right(текст, n)`,
`replace(текст, a, b)`, `concat(a, b, …)`, `split(текст, ",")`,
`join(список, ", ")`, `first(список)`, `last(список)`, `round(x, n)`,
`roundup`, `rounddown`, `ending(x, 90)`, `min`, `max`, `abs`. Это тот же
язык, на котором пишется формула колонки при импорте.

Фильтры внутри условия не пишутся: сначала запомните результат под именем
(`{% assign n = item.set | split: "," | size %}`) или возьмите функцию
(`len(item.pictures) > 0`).

## Списки

```
{% for p in item.pictures limit: 10 %}
<picture>{{ p }}</picture>
{% endfor %}

{% for o in options %}<Option>{{ o | trim }}</Option>{% endfor %}

{% for c in shop.categories %}
<category id="{{ c.id }}"{% if c.parent_id %} parentId="{{ c.parent_id }}"{% endif %}>{{ c.name }}</category>
{% endfor %}
```

Внутри цикла `forloop.index` считает с 1 (`forloop.index0` — с 0),
`forloop.first` и `forloop.last` говорят, где вы, `forloop.length` — сколько
всего. `limit: N` берёт первые N, `offset: N` пропускает N, `reversed`
разворачивает список; `{% break %}` выходит из цикла, `{% continue %}`
переходит к следующему элементу; `{% else %}` перед `endfor` выводится,
когда список пуст. `(1..5)` считает от 1 до 5.

## Имена

```
{% assign model = item.name | remove: item.brand | trim %}
{% assign memory = item.feature.memory | upcase %}
{% if memory == "1 TB" %}{% assign memory = "1024 ГБ" %}{% endif %}
<Model>{{ model }}</Model><MemorySize>{{ memory }}</MemorySize>

{% capture description %}
{{ item.name }} — {{ item.brand }}. {{ item.description | strip_tags | squish }}
{% endcapture %}
<description>{{ description | truncate: 3000 | cdata }}</description>
```

`assign` запоминает значение под именем, `capture` — всё, что напечатано
между его тэгами. Имя живёт от строки к строке, так что счётчик по строкам —
это `{% assign n = n | plus: 1 %}`.

## Один из нескольких

```
{% case item.feature.condition %}
{% when "new" %}<Condition>Новое</Condition>
{% when "used", "worn" %}<Condition>Б/у</Condition>
{% else %}<Condition>?</Condition>
{% endcase %}
```

Карта «это → то» — цвета магазина так, как их называет площадка, — это тот
же `case`: названия магазина в `when`, названия площадки в `assign`;
регистр при сравнении не важен. Названия, которых карта не упоминает,
остаются своими в ветке `else`:

```
{% case item.feature.color %}
{% when "Титановый синий", "Титановый чёрный" %}{% assign color = "Черный" %}
{% when "Синий" %}{% assign color = "Голубой" %}
{% else %}{% assign color = item.feature.color %}
{% endcase %}
<Color>{{ color }}</Color>
```

## Переменные профиля

Карточка под шаблоном держит значения, которые шаблон читает как
`vars.<имя>`: стоимость доставки, есть ли самовывоз, название компании для
этой площадки. Кто меняет цену, правит карточку, а не XML.

```
<delivery-options><option cost="{{ vars.delivery_cost }}" days="{{ vars.delivery_days }}"/></delivery-options>
{% if vars.pickup %}<pickup>true</pickup>{% endif %}
```

## Комментарии и текст как есть

`{% comment %} … {% endcomment %}` в файл не попадает; `{{! … }}` — то же,
в одну строку. `{% raw %} … {% endraw %}` печатает свои тэги как текст.

## Пробелы

Тэг, стоящий один на своей строке, забирает строку с собой, так что условие
или цикл не оставляют пустых строк. `{{-`, `-}}`, `{%-` и `-%}` съедают
пробелы и переносы рядом с собой.

## Строки

То, что стоит между `{% for item in rows %}` и `{% endfor %}` — или между
`{{#rows}}` и `{{/rows}}`, — повторяется для каждой строки, и строки идут
потоком: фид на пятьдесят тысяч товаров пишется строка за строкой и никогда
не держится в памяти целиком. Блок должен стоять на верхнем уровне шаблона,
не внутри условия. В потоке `forloop.length` и `forloop.last` неизвестны.

## Пределы

Шаблон может вкладывать тэги на 32 уровня, считать диапазон до 10 000,
делать 500 000 шагов и печатать 8 МБ на одну строку. За любой из этих границ
он останавливается, и ошибка называет строку: обычная причина — цикл внутри
цикла по большим спискам. Ошибка в тэге не даёт сохранить профиль; значение,
которое не удалось вычислить при сборке файла (деление на ноль),
останавливает сборку с номером строки.

## Шаблоны, написанные раньше

Тэги прежнего языка продолжают работать: `{{#item.pictures}} … {{ . }} …
{{/item.pictures}}` по разу на элемент, `{{#item.old_price}} … {{/…}}` только
когда значение есть, `{{^item.brand}} … {{/…}}` только когда его нет.

## Чего шаблон не делает

Шаблон описывает одну строку. То, что считается по всему файлу, — категории,
в которых в фиде действительно есть товары, первые картинки каждой, — это
значение, которое магазин вычисляет и передаёт шаблону, а не то, что шаблон
собирает сам. Если фиду нужно такое значение, а его нет, это просьба к
движку, а не более длинный шаблон.
