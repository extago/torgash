# Доставка кодов

**Покупатели → Доставка кодов.** Код подтверждения — для входа,
восстановления доступа, подтверждения телефона — из коробки уходит
письмом. Здесь у него появляются другие пути: SMS-шлюз, Telegram, любой
сервис, который принимает HTTP-запрос. Не модуль на каждого провайдера:
канал — это один запрос, который собирает магазин, тем же механизмом, что
и вебхук.

Покупателю предлагаются все включённые каналы, которые могут доставить код
на его адрес, в порядке поля **Порядок** — от меньшего. Каждый
отправленный код виден в **Покупатели → Коды подтверждения**.

Входить по телефону можно, только когда хоть один канал умеет доставить
код на телефон. До тех пор настройка магазина **Обязательный контакт
покупателя** возвращается к email, а строка телефона в аккаунте не
показывается.

## Новый канал

**+ Новый канал** предлагает готовые заполнения: **TurboSMS**, **Telegram
Gateway** (код приходит от официального аккаунта Telegram «Verification
Codes») и **Мой SMS-шлюз** — пустую заготовку. Заполнение только пишет
форму за вас и забывается: если провайдер поменял API, это исправляется
правкой канала, а не обновлением.

**Общее:**

* **Название** — покупатель видит его на кнопке «Отправить код через …».
* **Куда доставляет** — телефон, email или оба.
* **Только в эти страны** — коды стран, `UA PL`. Пусто — любые. Платному
  каналу стоит назвать свои страны: форму, которая шлёт коды по запросу,
  первым делом направляют на платные номера за границей.
* **Не больше кодов в день** — после этого канал перестаёт предлагаться до
  завтра. Отправка, которую провайдер отклонил сразу (неверный номер,
  страна, куда он не шлёт), не считается: за неё не списали деньги.

**Запрос:** **Метод**, **Адрес**, **Заголовки, по одному в строке**, **Тело
запроса** (JSON, поля формы или без тела) и **Секреты, по одному на строку:
имя=значение**. В адресе, заголовках и теле:

| Подстановка | Что это |
|---|---|
| `{{ phone }}` | номер, только цифры |
| `{{ phone_plus }}` | номер с `+` |
| `{{ email }}` | адрес почты |
| `{{ code }}` | шесть цифр |
| `{{ text }}` | всё сообщение, на языке покупателя |
| `{{ secret.name }}` | значение из поля секретов |

Секреты хранятся зашифрованными и больше не показываются: пустое значение
оставляет сохранённое, удалённая строка удаляет секрет. Из каждой ошибки,
которая попадает в журнал, они вырезаются.

**Чтение ответа** — как читать ответ провайдера, по правилу в строке:
`путь.в.ответе = значение`, несколько значений через `|`.

* **Отправлено, если выполнены ВСЕ**
* **Неверный номер, если выполнено ЛЮБОЕ** — покупателю скажут, что номер
  не может быть верным.
* **Не достучаться, если выполнено ЛЮБОЕ** — покупателю предложат другой
  способ.

Ответ не 2xx никогда не считается успехом.

## Как проверить

* **Проверить связь** — **Бесплатный проверочный запрос (GET)**: запрос,
  который доказывает, что ключ работает, ничего не отправляя, например
  баланс.
* **Отправить тестовый код** — одно настоящее сообщение. Стоит столько,
  сколько берёт провайдер, и считается в дневной лимит. Сначала сохраните
  форму: тест берёт сохранённое.

Выключенный канал покупателям не предлагается, но его собственный тест
работает.

## Что канал отклоняет

До отправки: приватный или зарезервированный адрес (то же правило, что у
вебхуков), адрес вне стран канала, городской номер для SMS и канал, который
исчерпал день. Код отправляется сразу, а не через очередь: «такой номер не
может быть верным» должно дойти до покупателя, пока он смотрит на экран.
