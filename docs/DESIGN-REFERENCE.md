# Дизайн темы default

Цвета, радиусы и раскладка витрины темы `default` и правила для контролов.
Сами числа живут в темах `torgash-light` / `torgash-dark` в
`resources/css/app.css`; здесь — что они значат и где применяются.

## Палитра

| Токен | Светлая | Тёмная | Где |
|---|---|---|---|
| primary | `#13B3F8` | `#13B3F8` | кнопки «Каталог», «В корзину», «Купить в 1 клик», ссылки, активные состояния |
| secondary | `#A56FFD` | `#A56FFD` | метка «Советуем» |
| accent | `#F5B400`, текст `#2B1E00` | так же | звёзды рейтинга, второстепенные акценты |
| success | `#00B259` | `#00B259` | метка «Новинка» |
| warning | `#FFECA8`, текст `#2B2100` | `#FFD75E` | метка «Акция»: бледно-золотая, с тёмным текстом |
| error | `#FF4F64` | `#FF4F64` | пилюля скидки «-10%» рядом с зачёркнутой ценой |
| info | `#2AB0ED` | `#2AB0ED` | информационные плашки |
| neutral | `#29303D` | `#1C2230` | тёмные полосы: шапка, подвал |
| base-100 / 200 / 300 | `#FFFFFF` / `#F5F6F9` / `#EAECF2` | `#1C2230` / `#12161E` / `#262D3D` | карточки и фон контента / фон страницы и плитки / второстепенные подложки |
| base-content | `#191B1E` | `#E7E9EE` | основной текст |

Радиусы: `8px` у полей, кнопок и переключателей (`--radius-field`,
`--radius-selector`), `12px` у карточек (`--radius-box`). Шрифт по умолчанию —
**Finlandica Text** (гротеск с широкими формами); Golos Text, Manrope и Rubik
выбираются в настройках темы. В тёмной теме шапка сливается с фоном — её
отделяет граница или тень.

## Раскладка витрины

- **Шапка**: тёмная (`.torgash-bar`), липнет при прокрутке. Бургер, логотип,
  акцентная кнопка «Категории» с иконкой сетки, широкий поиск, телефон; иконки
  сравнения, избранного, аккаунта и корзины со счётчиком.
- **Тонкая полоска над шапкой**: город слева, ссылки (О нас, Гарантия, Блог,
  Отзывы, Доставка и оплата, Контакты) справа.
- **Hero-слайдер**: на всю ширину, заголовок, описание и кнопка.
- **Строка преимуществ**: четыре пункта со скруглёнными иконками-бейджами
  (доставка / гарантия / оплата / поддержка: заголовок и мелкий текст).
- **Промо-карточки товарных линеек**: горизонтальный ряд с прокруткой,
  пастельные градиенты, бейдж «Хит продаж», заголовок, слоган, фото товара снизу.
- **Плитки категорий**: сетка на фоне base-200, фото по центру, подпись снизу.
- **Листинг товаров**: белые карточки в сетке; сверху мелкий серый код товара,
  название в две строки, звёзды и число отзывов, наличие, крупная жирная цена
  внизу. Табы секций («Популярные») с подчёркиванием активного.
- Нет фото — `<x-no-image>`.
- **Поле по краям — одно число** `--torgash-gutter` (12 / 16 / 24 px: телефон /
  от `sm` / от `lg`), в шаблоне — `px-(--torgash-gutter)`: строки шапки,
  мега-меню, полоса категорий, страница, секция «полосой», подвал, шапка
  телефона, полоса cookies. Своё `px-4` у полосы на всю ширину уводит её край
  от остальных (шапка стояла на 8 px левее контента, 2026-10-28).

## Инпуты: floating-label → fieldset (добавлено 2026-08-23)

daisyUI-паттерн `floating-label` (подпись поля лежит НА рамке инпута) заменён
везде на паттерн `fieldset`/`fieldset-legend` (подпись — обычная строка НАД
полем). Явная жалоба пользователя: "не особо нравится поле ввода, особенно
этот текст на бордюре, а не сверху". Затронуло 22 файла (админка ЦЕЛИКОМ +
витринные account/checkout-формы) — конверсия сделана скриптом
(`preg_replace_callback` по консистентному паттерну `<label class="floating-label">
<span>...</span>...</label>` → `<fieldset><legend>...</legend>...</fieldset>`),
6 файлов с доп. классами на `<label>` (`max-w-xs`, `flex-1`, `md:col-span-2` и
т.п.) или переносом `<span>` на новую строку скрипт не поймал — те 6 поправлены
вручную. `resources/views/components/admin/translatable-field.blade.php` (общий
компонент для JSONB-переводимых полей) — тоже переведён, это самый
высокоуровневый файл, автоматически чинит все места, где он используется.

## Иконки: Lucide (добавлено 2026-08-24)

**Набор — [Lucide](https://lucide.dev) 1.34.0, лицензия ISC.** Завендорен целиком
в `resources/icons/lucide/` (2035 SVG, 720 КБ) скриптом
`tools/vendor-lucide.php`. Берутся только `icons/*.svg` — в `lucide-static`
дополнительно лежат PNG-экспорты и иконочный шрифт, вместе ~47 МБ, они нам не
нужны. Каждый файл нормализован в одну строку без атрибута `class`, поэтому
компонент подставляет классы одним `str_replace` и никогда не парсит SVG в
рантайме.

**Правило: сторонний JS и ассеты — только MIT/BSD/ISC/Apache.** Движок
бесплатный, но с платными модулями: GPL-копилефт и per-seat коммерческие
лицензии одинаково не подходят (подробно — в PLAN.md, история с Fancybox).

**Использование** — только через `<x-icon>`, инлайновых `<svg>` в шаблонах
больше нет (проверено grep'ом):

    <x-icon name="shopping-bag" />              {{-- md, 16px --}}
    <x-icon name="trash-2" size="sm" />         {{-- 14px --}}
    <x-icon name="user" size="lg" class="text-primary" />

**Имена** — ровно те, что на lucide.dev/icons, никакого своего словаря. Доступны
все 2035 икон: модуль называет что угодно и не патчит ядро ради новой иконки.
Имя приходит и данными — из `admin_menu[].icon` в манифесте модуля и из
PHP-массивов вроде плиток дашборда.

**Четыре размера, не семь.** До перехода в коде было семь разных пар
(`h-3`…`h-8`, включая нестандартный шаг `h-4.5`). Теперь пресеты:
`sm` = 14px, `md` = 16px (по умолчанию), `lg` = 20px, `xl` = 24px. Явный
`class="h-*"` всё ещё побеждает пресет — но именно побеждает, а не
складывается с ним: компонент видит `h-`/`w-` в переданных классах и не
добавляет свой (иначе исход решал бы порядок правил в CSS).

**Неизвестное имя.** В `APP_DEBUG=true` — исключение с подсказкой; в проде —
иконка просто не рисуется. Опечатка в манифесте стороннего модуля не должна
ронять админку живого магазина, но и молча превращаться в плюсик (как было
раньше с `default =>` в старом `match`) тоже не должна.

**Поиск по коду.** Все имена в использовании валидируются одной командой:

    grep -rho 'x-icon name="[a-z0-9-]*"' --include=*.blade.php resources themes modules \
      | sed 's/.*name="//;s/"//' | sort -u \
      | while read n; do [ -f "resources/icons/lucide/$n.svg" ] || echo "MISS $n"; done

## Шкала размеров контролов на витрине (добавлено 2026-10-06)

Размер задаётся ОДНИМ местом — `resources/css/app.css`, блок «The storefront's
one scale of controls», — а не классом в шаблоне. Рычаги daisyUI:
`--size-field` (высота кнопок/полей/селектов = ×10, `-sm` ×8, `-lg` ×12) и
`--size-selector` (галочки/переключатели/радио = ×6); оба выписаны в темах.

| Уровень | Высота | Где |
|---|---|---|
| по умолчанию | 40px | поле и кнопка рядом с полями |
| `-sm` | 36px (на витрине переопределено с 32) | компактное действие: в карточке, в строке, ссылка-кнопка; текст остаётся 14px |
| `-lg` | 48px | ГЛАВНОЕ действие страницы: купить, оформить заказ |
| галочка/переключатель/радио | 20px | всегда один размер, без `-sm` |

Не использовать на витрине: `-xs`, `checkbox-sm`/`toggle-sm`/`radio-sm`,
высоту контрола через `h-10`/`h-11`, размер шрифта вида `text-[0.9375rem]` —
только шкала Tailwind (`text-xs/sm/base/lg…`). Админка живёт на шкале
daisyUI как есть.
