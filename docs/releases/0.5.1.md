## What's new

**In short:** a backup that a storage refused is no longer lost. An S3 storage now says how many times a part of a file is tried (10 by default, where the library tried 3 — and Backblaze's "internal incident" over two parts of a 2.4 GB archive outlasted them), an upload given up on is aborted so the bucket does not keep and bill its parts, every kind of storage gets a second try, and a copy that was not stored is sent again from the copy that was — without the backup being made anew.

### Backups
- **Attempts for each part of a file** — a setting of an S3 storage (1–100, 10 by default). A big file goes up in parts of five megabytes; a part refused with a server error is sent again after a pause that grows, up to this many times. Backblaze B2 has such moments: 10 outlasts most of them, 30 the longer ones.
- A multipart upload that was given up on is **aborted** in the bucket: before, its parts stayed there — billed, and shown nowhere by Backblaze.
- A storage that refuses the file at all — SFTP, FTP, WebDAV, a folder, a disk or a bucket — is **tried once more** after a short pause before the copy is marked "not stored".
- **"Send again"** beside a copy not stored on the Backups list: the file is taken from the copy that is kept (the server's first) and sent to that storage as a background task. The backup is not made anew for it. The run reads "done" once every copy is there, and the storage's keeping rules run for it.

## Что нового

**Главное:** копия, которую не приняло хранилище, больше не пропадает. У хранилища S3 появилась настройка, сколько раз отправлять часть файла (по умолчанию 10, библиотека пробовала 3 — и «internal incident» у Backblaze на двух частях архива в 2,4 ГБ их пересидел); незавершённая загрузка отменяется, чтобы бакет не хранил и не оплачивал её части; любое хранилище получает вторую попытку; несохранённая копия отправляется ещё раз из той, что хранится, — без пересборки.

### Резервные копии
- **Попыток на каждую часть файла** — настройка хранилища S3 (1–100, по умолчанию 10). Большой файл уходит частями по пять мегабайт; часть, отвергнутую ошибкой сервера, отправляют снова после растущей паузы, до стольких раз. У Backblaze B2 такие моменты бывают: 10 пересиживает большинство, 30 — затяжные.
- Многочастная загрузка, от которой отказались, **отменяется** в бакете: раньше её части оставались там — оплачивались, а Backblaze их нигде не показывал.
- Хранилище, которое вовсе не приняло файл, — SFTP, FTP, WebDAV, папка, диск или бакет, — **пробуется ещё раз** после короткой паузы, и только потом копия помечается «не сохранена».
- **«Отправить ещё раз»** рядом с несохранённой копией в списке копий: файл берётся из той копии, что хранится (сначала серверной), и отправляется в это хранилище фоновой задачей. Копия не пересобирается. Запуск становится «готово», когда все копии на месте, и для хранилища запускаются правила хранения.
