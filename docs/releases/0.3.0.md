## What's new

**In short:** pages kept ready for guests, several times faster; merging values of a characteristic; import from the server console; a faster delivery estimate.

### Page cache
- A page a guest has opened is kept, and the next guests get it ready-made: the home page, the catalogue and categories, filter pages, product pages, brands, the blog and the shop's pages. On our test server a product page opens in 0.24 s instead of 0.84 s, the home page in 0.30 s instead of 1.04 s.
- Switched on in Settings → Store → "Page cache" → "Keep pages ready for guests"; off by default. The same group sets how long a page is kept (60 minutes by default) and which pages are always drawn afresh.
- What is a visitor's own stays theirs: the basket, the wishlist, the comparison, the chosen town, "Viewed recently", the delivery estimate and the CAPTCHA are drawn for each visitor.
- Signed-in customers and staff always get a freshly drawn page. Search, arbitrary combinations of filters, the basket and checkout are never kept.
- A change in the admin throws the kept pages away by itself. When a sale, a banner or a label starts or ends on schedule, the page is kept only until then. When a product's stock changes, only the pages that show it are drawn again.
- Product views, popularity and "Viewed recently" count for guests served a kept page too.
- System → Cache and sessions has a "Pages kept for guests" card: how many pages are kept and the space they take, when they were last all thrown away and why, why some pages were not kept, and a button to throw them away — for a template or a file changed on the server.

### Delivery
- The delivery estimate on a product page for a visitor who chose a town (Nova Poshta) took about 0.6 s on every view; now about 0.05 s. The price is remembered for 30 minutes, and the town's branches are loaded only when they are out of date.

### Characteristics
- Values of a characteristic can be merged. Two spellings of one colour, each with its own products, filter tick and filter page, become one value with "Merge values" on the characteristic's page, which also warns about values written alike and suggests what to merge. Products, markup rules, labels, filter pages and the brand page move to the value that stays; the old addresses redirect to it.
- Merged spellings are remembered: the import and old filter addresses still find the value by them.
- A new value written like an existing one (letter case, ё and е, dashes, spaces, quotes) is refused.

### Import
- Import from the server console: `php artisan exim:import file.csv` reads the file with the same presets and columns as the Import screen and runs as a background task with its counts. `--dry-run` checks without writing anything.

### Landings
- `:root` in a landing's CSS works: variables defined there used to reach nothing.
- A "#…" link inside a landing scrolls to its place, unfolds a folded landing first and stops below the sticky header.
- The landings help explains what a landing takes from the page and how to cut it off. The Media module has a help of its own.

### Fixed
- Blog: "A row of equal cards" showed the cards in one column; now they stand side by side, three or four in a row. Wide covers under the "Pad" thumbnail fit had white bands; a cover now fills its frame, and the update rebuilds the thumbnails of covers already uploaded.
- Import: a row that matched nothing and had no name (a mistyped SKU in a price list) rolled back the whole file. It is now skipped with a note, and "Check" lists it.

### Other
- The licences of the third-party scripts, fonts, icons and data that come with the engine are listed in THIRD-PARTY.md, included in the distribution.

## Что нового

**Главное:** страницы, готовые для гостей, — в несколько раз быстрее; объединение значений характеристики; импорт из консоли сервера; быстрая оценка доставки.

### Кэш страниц
- Страница, которую открыл гость, сохраняется, и следующие гости получают её готовой: главная, каталог и категории, страницы фильтров, страницы товаров, бренды, блог и страницы магазина. На нашем тестовом сервере страница товара открывается за 0,24 с вместо 0,84 с, главная — за 0,30 с вместо 1,04 с.
- Включается в Настройки → Магазин → «Кэш страниц» → «Держать страницы готовыми для гостей», по умолчанию выключено. Там же — сколько хранить страницу (по умолчанию 60 минут) и какие страницы всегда рисовать заново.
- Личное остаётся личным: корзина, избранное, сравнение, выбранный город, «Вы недавно смотрели», оценка доставки и капча рисуются для каждого посетителя свои.
- Вошедшие покупатели и сотрудники всегда получают свежую страницу. Поиск, произвольные сочетания фильтров, корзина и оформление заказа не сохраняются никогда.
- Изменение в админке само выбрасывает сохранённые страницы. Если акция, баннер или ярлык начинаются или заканчиваются по расписанию, страница хранится только до этого момента. Когда меняется остаток товара, заново рисуются только страницы, где он показан.
- Просмотры товаров, популярность и «Вы недавно смотрели» учитываются и для гостей, получивших готовую страницу.
- В Система → Кэш и сессии появилась карточка «Страницы для гостей»: сколько страниц сохранено и сколько места они занимают, когда их все выбросили последний раз и почему, почему какие-то страницы не сохранились, и кнопка «Выбросить сохранённые страницы» — для шаблона или файла, изменённого на сервере.

### Доставка
- Оценка доставки на странице товара для посетителя с выбранным городом («Новая почта») занимала около 0,6 с при каждом показе, теперь около 0,05 с. Цена запоминается на 30 минут, а отделения города загружаются, только когда устарели.

### Характеристики
- Значения характеристики можно объединить. Два написания одного цвета, у каждого свои товары, галочка в фильтре и страница фильтра, становятся одним значением через «Объединить значения» на странице характеристики — она же предупреждает о значениях, написанных одинаково, и подсказывает, что объединить. Товары, правила наценки, ярлыки, страницы фильтров и страница бренда переходят к значению, которое остаётся; старые адреса ведут на него.
- Объединённые написания запоминаются: импорт и старые адреса фильтров по-прежнему находят значение по ним.
- Новое значение, написанное так же, как уже существующее (регистр, ё и е, дефисы, пробелы, кавычки), не принимается.

### Импорт
- Импорт из консоли сервера: `php artisan exim:import file.csv` читает файл с теми же пресетами и колонками, что и экран «Импорт», и выполняется фоновой задачей со своими счётчиками. `--dry-run` проверяет, ничего не записывая.

### Лендинги
- `:root` в CSS лендинга работает: переменные, объявленные там, раньше никуда не доходили.
- Ссылка «#…» внутри лендинга прокручивает к своему месту, сначала разворачивает свёрнутый лендинг и останавливается под закреплённой шапкой.
- Справка по лендингам объясняет, что лендинг получает от страницы и как это отрезать. У модуля «Медиатека» появилась своя справка.

### Исправлено
- Блог: «Ряд одинаковых карточек» показывал карточки в один столбец — теперь они стоят рядом, по три или четыре. У широких обложек при вписывании «Pad» были белые полосы — теперь обложка заполняет рамку, а обновление пересоздаёт миниатюры уже загруженных обложек.
- Импорт: строка, которая ни с чем не совпала и не имела названия (опечатка в артикуле в прайсе), откатывала весь файл. Теперь она пропускается с пометкой, а «Проверить» показывает её в списке.

### Прочее
- Лицензии сторонних скриптов, шрифтов, значков и данных, которые входят в движок, перечислены в THIRD-PARTY.md — он входит в дистрибутив.
