## What's new

**In short:** an automation no longer loses a message when the network drops it — the action is tried again on its own, as many times and as often as you choose — and a template can say "only if there is one", so a product without options gets no empty "Options:".

### Automations
- A receiver that could not be reached — the host down, the connection to Telegram dropped on the way, a "try later" (429) or an error on the receiver's side (5xx) — is tried again: that one action, not the rest of the rule, so a status already changed or a webhook already taken is never repeated. Two settings in Settings → Automations: how many times (3 by default; 0 switches it off) and after how many minutes (2). Before, such a failure was final and the message was lost.
- A refusal — a wrong token, a chat not found, any 4xx — is never retried: it stays in the log until somebody fixes it.
- The run log has a "retry" tab: every attempt is a row — "Attempt 1 of 4, next in 2 min: cURL error 28…" — and the last one says sent or failed.
- A Telegram message whose connection drops is tried three times at once before it waits for the interval. A message Telegram took but did not confirm in time may arrive twice; a lost one would be worse.
- In a message or a webhook body a block named after a value is printed only when the value is there: `{{#item.options_text}} (options: {{ item.options_text }}){{/item.options_text}}` leaves no bare "options:" and no empty brackets on a product without options; the same for a coupon, a comment, a manager. The module's documentation shows how.

## Что нового

**Главное:** автоматизация больше не теряет сообщение, когда сеть его обрывает, — действие повторяется само, столько раз и так часто, как вы решите, — а шаблон умеет «только если есть», так что у товара без опций не останется пустого «Опции:».

### Автоматизации
- Получатель, до которого не удалось достучаться, — хост лежит, соединение с Telegram оборвалось по пути, ответ «попробуйте позже» (429) или ошибка на стороне получателя (5xx), — получает повтор: именно это действие, а не всё правило, так что уже изменённый статус или уже принятый вебхук не повторяются. Две настройки в Настройки → Автоматизации: сколько раз (по умолчанию 3; 0 выключает) и через сколько минут (2). Раньше такая ошибка была окончательной, и сообщение терялось.
- Отказ — неверный токен, чат не найден, любой 4xx — не повторяется никогда: он остаётся в журнале, пока его не исправят.
- В журнале запусков вкладка «повтор»: каждая попытка — строка «Попытка 1 из 4, следующая через 2 мин: cURL error 28…», последняя — «отправлено» или «не удалось».
- Сообщение в Telegram при обрыве соединения пробуется трижды подряд и только потом ждёт интервала. Сообщение, которое Telegram принял, но не успел подтвердить, может прийти дважды; потерянное было бы хуже.
- В тексте сообщения или теле вебхука блок, названный по значению, печатается только когда значение есть: `{{#item.options_text}} (опции: {{ item.options_text }}){{/item.options_text}}` не оставляет голого «опции:» и пустых скобок у товара без опций; так же для купона, комментария, менеджера. В документации модуля показано, как.
