## What's new

**In short:** uploading modules and themes from the admin can now be switched off on the server, so a stolen administrator password is no longer a way to put code on it. Sizes of one clothing card are one page to Google and Yandex, form errors are in Russian and Ukrainian, and a customer can confirm the email they registered with.

### Security
- **Uploading code from the admin can be switched off.** Put `TORGASH_CODE_UPLOAD=false` into `.env`: the "Upload a module" and "Upload a theme" buttons disappear, and the server refuses an upload even from an administrator. Modules and themes are then added as folders through the server itself (`modules/`, `themes/`). Installing, switching on and off and deleting what is already there works as before, and so do signed engine updates. Admin → System shows whether uploading is on.

### Clothing: sizes and search engines
- **One page per card for search engines.** The page of every size of one colour now points search engines (canonical) at one product of that card — the one created first; the sitemap lists only that one. Colours stay separate pages. A canonical address typed on a product still wins.
- **The sitemap no longer lists products marked "noindex".**
- **"No two products offer a search engine the same title"** no longer reports the sizes of one card, and compares the title the page really shows — a title an SEO template makes different (with the size or colour in it) is no longer a duplicate.

### Fixes
- Form errors the engine did not word itself ("The password field must be at least 8 characters.") came in English on a Russian or Ukrainian storefront and admin. They are now translated.
- An email left unconfirmed at registration (when the shop asks no code there) showed "not confirmed yet" in the account with no way to confirm it: typing the same address under "Change" was refused. There is now a "Confirm it" link beside the warning, which sends a code to that address.

## Что нового

**Главное:** загрузку модулей и тем через админку теперь можно выключить на сервере — тогда украденный пароль администратора уже не позволяет положить на него код. Размеры одной карточки одежды — одна страница для Google и Яндекса, ошибки в формах — на русском и украинском, а покупатель может подтвердить почту, с которой зарегистрировался.

### Безопасность
- **Загрузку кода через админку можно выключить.** Впишите в `.env` строку `TORGASH_CODE_UPLOAD=false`: кнопки «Загрузить модуль» и «Загрузить тему» пропадут, а сервер откажет в загрузке даже администратору. Модули и темы тогда добавляются папкой через сам сервер (`modules/`, `themes/`). Установка, включение, выключение и удаление того, что уже есть, работают как раньше, подписанные обновления движка — тоже. Включена ли загрузка, видно в Админка → Система.

### Одежда: размеры и поисковики
- **Одна страница на карточку для поисковиков.** Страница любого размера одного цвета теперь указывает поисковику (canonical) на один товар этой карточки — созданный первым; в карте сайта только он. Цвета остаются отдельными страницами. Адрес canonical, вписанный в товаре вручную, по-прежнему главнее.
- **Товары с «noindex» больше не попадают в карту сайта.**
- **Проверка «Ни у каких двух товаров не одинаковый заголовок для поисковика»** больше не считает дублями размеры одной карточки и сравнивает заголовок, который действительно видно на странице: если SEO-шаблон делает заголовки разными (с размером или цветом), это уже не дубль.

### Исправления
- Ошибки в формах, которые движок не формулирует сам («The password field must be at least 8 characters.»), на русской и украинской витрине и в админке приходили по-английски. Теперь они переведены.
- Почта, не подтверждённая при регистрации (когда магазин не спрашивает там код), висела в кабинете как «ещё не подтверждена», и подтвердить её было нечем: тот же адрес в «Изменить» не принимался. Теперь рядом с предупреждением есть ссылка «Подтвердить» — на этот адрес уходит код.
