## What's new

**In short:** the shop no longer spends its server on scanners. A request for `/.env`, `/wp-login.php` and the like gets a bare "not found" page instead of the whole storefront. The sitemap, the product page and the admin's home page ask the database less.

### Speed
- **Scanners get a bare 404.** Robots that look for other software's files (`/.env`, `/wp-login.php`, `/backup.zip`) and requests for pictures that are not there used to be answered with the shop's full "Page not found": header, menu, footer, 26 database requests each. On a live shop that was about a third of everything the server did in a day. They now get a plain page that asks the database for nothing.
- A visitor who follows a dead link still sees "Page not found" inside the shop, with the search and the way home. Redirects from old addresses work as before, addresses ending in `.php` included.
- **The sitemap is built with one database request for the products' categories** instead of one per product: 579 fewer on a shop of that many products.
- **The product page asks less:** the product's variations once instead of twice, and the logos of payment and delivery methods in one request instead of one per method.
- **The Brands page reads every logo in one request.**
- **Every page of the shop reads its languages and currencies once** instead of twice.
- **The admin's home page counts what is waiting once** — new orders, enquiries, reviews, backups. It used to count everything twice, for the bell and for the "Needs attention" card.

### Updates screen
- **An update's notes are shown whole.** The box no longer scrolls inside itself, which looked like text cut off: it is shown short, with "Show in full" and "Collapse".
- **A shop several versions behind reads the notes of every version it gets,** newest first, each under its number. Before, it saw only the latest version's.

Nothing needs to be done by hand after this update.

## Что нового

**Главное:** магазин больше не тратит сервер на сканеры. Запрос `/.env`, `/wp-login.php` и подобных получает голую страницу «не найдено» вместо всей витрины. Карта сайта, страница товара и главная админки меньше спрашивают базу.

### Скорость
- **Сканерам — голая 404.** Роботы, которые ищут файлы чужих программ (`/.env`, `/wp-login.php`, `/backup.zip`), и запросы картинок, которых нет, получали полную «Страница не найдена» магазина: шапка, меню, подвал, 26 запросов к базе на каждый. На живом магазине это была примерно треть всей работы сервера за сутки. Теперь им отдаётся простая страница, которая базу не спрашивает вовсе.
- Посетитель, пришедший по мёртвой ссылке, по-прежнему видит «Страница не найдена» внутри магазина, с поиском и ссылкой на главную. Перенаправления со старых адресов работают как раньше, в том числе с адресов на `.php`.
- **Карта сайта строится с одним запросом категорий товаров** вместо запроса на каждый товар: на магазине с 579 товарами — на 579 запросов меньше.
- **Страница товара спрашивает меньше:** варианты товара один раз вместо двух, логотипы способов оплаты и доставки — одним запросом вместо запроса на каждый способ.
- **Страница «Бренды» читает все логотипы одним запросом.**
- **Каждая страница магазина читает языки и валюты один раз** вместо двух.
- **Главная админки считает, что ждёт внимания, один раз** — новые заказы, обращения, отзывы, резервные копии. Раньше всё считалось дважды: для колокольчика и для карточки «Требует внимания».

### Экран обновлений
- **Заметки к обновлению показываются целиком.** Блок больше не прокручивается внутри себя, из-за чего текст выглядел обрезанным: он показан коротко, с кнопками «Показать полностью» и «Свернуть».
- **Магазин, отставший на несколько версий, читает заметки каждой версии, которую получает,** новые сверху, каждая под своим номером. Раньше он видел заметки только последней.

После этого обновления ничего делать вручную не нужно.
